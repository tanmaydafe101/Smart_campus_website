1. INTRODUCTION

Project Overview

A Smart Campus Issue & Facility Management System provides reliable digital services to report classroom, laboratory, Wi-Fi, and electrical issues, assign campus technicians, and manage resolution workflows. The system seamlessly connects students, technicians, and administrators through native Android mobile clients, responsive web portals, Core PHP REST APIs, and a relational MySQL database.

Primary Contribution & Focus Area:
  • Automated Issue Lifecycle: Standardized 5-stage state machine (OPEN ➔ ASSIGNED ➔ IN_PROGRESS ➔ RESOLVED ➔ CLOSED).
  • Dual Web & Mobile Portals: Dedicated Student Self-Service Portal and Administrator Command Center.
  • Secure Backend Architecture: Core PHP REST APIs using PDO transactions, BCrypt password hashing, and stateless HMAC tokens.
  • Photo Evidence Uploads: Safe multipart file handling with strict MIME verification (JPG, PNG, WebP) up to 5MB.
  • Automated SLA Engine: Dynamic calculation of target resolution deadlines based on issue priority.
  • Audit Trail & Discussion: Full status transition history (ticket_history) and real-time chat (ticket_comments).

3. PROBLEM DEFINITION

Problem Statement
Current Campus Challenges:

In educational institutions, campus maintenance complaints (broken fans, Wi-Fi connectivity faults, dim projectors, leaking water coolers, damaged classroom desks) are recorded in manual paper registers, verbal complaints to peons, or disconnected WhatsApp chats.

✖ Unrecorded Complaints:
Physical registers are misplaced or forgotten, leading to prolonged equipment downtime.
✖ Zero Status Visibility:
Students have no way to know whether their issue was received, assigned, or is being repaired.
✖ Misallocation of Technicians:
Electrical issues get assigned to carpenters due to lack of category classification.
✖ Lack of SLA Accountability:
College authorities cannot track recurring defects, overdue deadlines, or staff performance.
Core Problem Statement:
To design and develop a secure, automated, role-based Smart Campus Issue & Facility Management System that enables students to report campus issues via mobile or web with photo attachments, allows administrators to assign technicians and monitor live metrics, and provides end-to-end transparent status tracking.

4. PROPOSED SYSTEM

Architecture & Modules
Core System Modules:
  • 1. Authentication: Role-based access (Student, Technician, Admin) with BCrypt & HMAC tokens.
  • 2. Category & Location: Campus hierarchy covering Academic Blocks, Labs, Rooms, and Issue Categories.
  • 3. Issue Reporting: Form with priority selector, location dropdown, and multipart photo upload.
  • 4. Workflow Tracking: Enforces state machine (OPEN ➔ ASSIGNED ➔ IN_PROGRESS ➔ RESOLVED ➔ CLOSED).
  • 5. Admin Assignment: Back-office assignment of campus technicians with notes.
  • 6. Analytics & Reports: KPI counters, Doughnut/Bar charts, and CSV report export.
Database Schema Covered (MySQL):
• users: Students, Technicians, Administrators
• categories: Wi-Fi, Electrical, Furniture, Computer Lab, Cleanliness
• locations: Campus buildings, classrooms, labs, and QR tokens
• tickets: Master issue records with priority, photo, and SLA timestamps
• ticket_history: Immutable transition log with user IDs and comments
• ticket_comments: Interactive communication between reporter and staff
Zero Framework Bloat: Built using Core PHP with PDO prepared statements and Native Android Java for maximum speed and simplicity.

5. PROJECT FLOW

Workflow Execution
Step 1 User Request: Student logs in via Android Mobile App or Student Web Portal.
Step 2 Issue Submission: Selects building, room, issue category, priority, and attaches optional photo.
Step 3 Controller Processing: PHP REST API validates input, generates unique Ticket Code (e.g., TICK-2026-0001), and computes SLA deadline.
Step 4 Database Storage: Record inserted into tickets table with status OPEN and logged in ticket_history.
Step 5 Admin Allocation: Administrator views complaint on dashboard, verifies photo, and assigns a campus technician.
Step 6 Field Resolution: Technician arrives on site, updates status to IN_PROGRESS, completes repair, and marks RESOLVED.
Step 7 Verification & Closure: Student inspects repair, adds verification comment, and ticket status transitions to CLOSED.

9. FUTURE SCOPE

Roadmap
Potential Enhancements for Future Iterations:
  • Push Notifications & SMS Alerts: Integrate Firebase Cloud Messaging (FCM) or Twilio to notify students instantly when status changes.
  • QR Code Classroom Scanner: Camera-based QR code scanning on classroom walls to auto-fill building and room numbers without manual selection.
  • AI-Powered Image Severity Detection: Utilize lightweight computer vision models to verify uploaded damage photos and flag critical hazards.
  • Automated Technician Dispatch: Rule-based auto-assignment algorithm matching issue categories with nearest on-duty campus technicians.
  • IoT Sensor Integration: Connect smart electrical meters and water tank level sensors to auto-trigger complaints before human detection.
  • Multi-Campus Scalability: Extend database schema for university groups managing multiple affiliate colleges under one master portal.
