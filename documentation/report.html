1. Introduction

College and university campuses are large, active educational environments consisting of classroom complexes, computer laboratories, research centers, libraries, administrative offices, and student hostels. Keeping campus physical infrastructure in working order—including classroom projectors, lab computers, air conditioners, fans, lighting, network access points, and water sanitation fixtures—is vital for supporting smooth daily academic activities.

Traditionally, facility maintenance and complaint handling on campuses have relied on manual physical logbooks maintained in departmental offices, verbal messages passed to office attendants, or informal emails. This manual process has major flaws: complaints often lack essential specifics (such as the exact room number, bench location, or photo evidence of physical damage); manual registers give students zero visibility into whether their complaint was reviewed or assigned; and facility supervisors have no easy way to track recurring equipment faults, technician response delays, or departmental performance.

To overcome these challenges, the Smart Campus Issue & Facility Management System was developed as a modern, web and mobile-based platform. The system allows students, faculty members, and campus staff to quickly report physical defects and equipment breakdowns directly from their web browsers or Android smartphones. Every submitted ticket is assigned a unique tracking number, tagged with specific location coordinates, categorized by infrastructure domain, and supported by photo evidence.

During the summer internship, my individual contribution was the MySQL Database and Backend Integration of the system. I designed the normalized relational database schema and connected the PHP backend to MySQL using PDO so that user accounts, category definitions, room locations, complaint tickets, technician assignments, and status histories are stored permanently and retrieved reliably for the student portal, admin dashboard, and reporting views.

This report documents the project, the objectives of my contribution, the technologies used, the modules and tasks completed, the outcomes achieved, the challenges faced along with the solutions applied, and my overall conclusions. It reflects both the technical competencies I developed and my role in building a dependable, fully functional campus management system.

2. Project Overview

The Smart Campus Issue & Facility Management System is a full-stack web and mobile application designed to digitize the end-to-end handling of campus maintenance complaints. A student logs into the Student Portal, fills in issue details, attaches a photo, and submits the ticket. The backend validates and records the issue, while the Admin Dashboard allows facility administrators to assign tickets to technicians, monitor resolution progress, and review analytics. The main components are listed below; the database layer was my primary responsibility.
Component Description
Student Web Portal (PHP) Student registration, secure login, issue submission with photo upload, and personal complaint tracking.
Admin Dashboard (PHP) KPI metric counters, ticket assignment to technicians, status updates, category setup, and CSV export.
Backend REST APIs (PHP) RESTful endpoints for authentication, role verification, complaint submission, and data queries.
Database (MySQL) – My Contribution Permanent storage of users, locations, categories, complaints, and ticket history with quick query retrieval.
Android App (Java / XML) Native Android client communicating with the backend APIs for student and technician on-the-go access.
Whole Team System testing, cross-module integration, API schema alignment, and project documentation.

5.1 Database Design in MySQL:
The database stores all operational information needed by the application. A users table holds accounts for students, technicians, and administrators. A categories table lists departments like Electrical and Hardware. A locations table maps campus blocks and room numbers. A tickets table holds every reported issue, its priority, photo attachment, and assigned technician. Relational tables ensure data consistency and prevent duplication.

5.2 Database Tables and Schema Structure:
The primary tables and their relationships are structured so that any ticket's full lifecycle, reporting student, and assigned technician can be fetched with a single indexed join query.

5.3 Connecting Backend to MySQL via PDO:
The backend connects to MySQL once per request using PDO. Prepared statements ensure that database operations are fast and completely immune to SQL injection.

// backend/config/database.php - PDO Connection class Database { private $host = "localhost"; private $db_name = "smart_campus"; private $username = "root"; private $password = ""; public $conn; public function getConnection() { try { $dsn = "mysql:host={$this->host};dbname={$this->db_name};charset=utf8mb4"; $this->conn = new PDO($dsn, $this->username, $this->password, [ PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION, PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC ]); } catch(PDOException $e) { error_log("Connection error: " . $e->getMessage()); } return $this->conn; } }
